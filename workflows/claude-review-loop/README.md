# claude-review-loop

Automated PR review + iterative fix loop, powered entirely by your Claude Pro/Max subscription
via `CLAUDE_CODE_OAUTH_TOKEN`. No third-party reviewers or per-PR add-on billing.

**Status**: experimental. Self-review has known bias (reviewer and fixer are the same model).
See `docs/decisions.md` for the trade-off analysis.

## What it gives you

- Every PR auto-reviewed by Claude (Opus 4.7) against a strict, editable rubric.
- Each review ends with a machine-readable `<!-- claude-review:summary -->` block.
- A second workflow parses that block and decides: pass, stop (max iterations), or run Claude
  again to address feedback. Loop continues until pass or `MAX_ITER` (default 3) is reached.
- Opt-out per PR via the `no-claude-loop` label.

## Requirements on the target repo

| Requirement | How |
|---|---|
| Claude GitHub App installed | Run `/install-github-app` inside `claude` (Claude Code CLI). |
| Secret `CLAUDE_CODE_OAUTH_TOKEN` | Generated by `claude setup-token`, added under repo Settings → Secrets. |
| GitHub Actions enabled | Default for new repos. |

## Install into a repo

```bash
~/dev/agentic-kit/workflows/claude-review-loop/install.sh /path/to/target/repo
```

The installer:

1. Verifies the target is a git repo.
2. Copies these files in (asking before overwriting):
   - `.github/workflows/claude-code-review.yml`
   - `.github/workflows/claude-loop.yml`
   - `.github/PR-REVIEW-RUBRIC.md`
3. Appends a documentation block into `AGENTS.md` (or `CLAUDE.md`) bracketed by
   `<!-- claude-review-loop:begin/end -->` markers. Idempotent.
4. Prints a post-install checklist (secret, label, commit reminder).

Re-running the installer is safe — existing identical files are skipped, modified files are
shown as a diff before overwrite.

## Update an installed repo

Pull the latest in this kit, then re-run the same install command. You'll be asked before any
file is overwritten. To inspect a diff first:

```bash
diff -u /path/to/target/repo/.github/workflows/claude-loop.yml \
        source/.github/workflows/claude-loop.yml
```

## Customizing per-repo

After installation, edit the copies inside the target repo. Common knobs:

- **Iteration cap and threshold**: `env:` block at top of `claude-loop.yml`
  (`MAX_ITER`, `MIN_CONFIDENCE`).
- **Review strictness**: edit `.github/PR-REVIEW-RUBRIC.md`. The workflow reads it at review
  time, so no workflow code change is needed.
- **Reviewer/fixer model**: change `--model` in the `claude_args` of either workflow.

Per-repo edits are intentionally local — this is a one-shot scaffold, not a live-synced
include. See `docs/decisions.md` for why.

## Known limitations

- **Self-grading bias**: same model writes the code (locally) and grades it (in CI). Use this
  as a quality lift over zero reviews; do not treat the score as objective.
- **OAuth token expiry**: `CLAUDE_CODE_OAUTH_TOKEN` is short-lived in some setups (see
  Troubleshooting below).
- **Subscription quota**: each loop iteration burns Pro/Max quota. `MAX_ITER=3` is the brake.

See `docs/decisions.md` for the full rationale.

## Troubleshooting

### Auth failures (`Could not resolve authentication credentials`, `validateHeaders`)

This is the most common failure mode. The OAuth token issued by `claude setup-token` does
not auto-refresh and has been observed to expire within ~1h in some setups
([upstream issue](https://github.com/anthropics/claude-code/issues/11016)). Users upgrading
between Pro and Max plans have also reported intermittent `validateHeaders` failures
([upstream issue](https://github.com/anthropics/claude-code-action/issues/1281)).

**Fix:**

```bash
claude setup-token                          # generates a fresh OAuth token
gh secret set CLAUDE_CODE_OAUTH_TOKEN       # paste the new value when prompted
gh run rerun <run-id>                       # re-run the failed workflow
```

Verify the secret exists at any time with `gh secret list` (it should show
`CLAUDE_CODE_OAUTH_TOKEN` with an "Updated" timestamp).

### Loop posts `summary block missing or unparseable`

The reviewer didn't emit the required `<!-- claude-review:summary -->` block. The loop refuses
to guess and skips. Inspect the actual review body in the Actions log to see what was
returned. Typical fixes:

- Strengthen `.github/PR-REVIEW-RUBRIC.md` so the block format is unmissable.
- Re-run by closing and reopening the PR (re-fires `pull_request: opened`).

### Loop never triggers after Claude pushes a fix

Pushes from `github-actions[bot]` (i.e. via the default `GITHUB_TOKEN`) **do not** retrigger
workflows by design — this is GitHub's loop-avoidance behavior. The Claude GitHub App's
pushes do trigger workflows; confirm the App is installed at
`https://github.com/<owner>/<repo>/settings/installations`. If pushes are coming from
`github-actions[bot]` instead, the workflow is misconfigured — re-run `/install-github-app`.

### Loop ran on a PR you didn't want reviewed

Add the `no-claude-loop` label. The review workflow's `if:` guard checks for it on every
trigger, so adding the label mid-PR stops further iterations.

### Subscription quota exhausted

Symptom: workflow runs but Claude returns a rate-limit error. Options:

- Wait for the quota window to reset.
- Lower `MAX_ITER` in `.github/workflows/claude-loop.yml`.
- Add `no-claude-loop` to PRs that don't need automated review.
